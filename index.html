A Python runner connects three local model tiers with targeted web lookup and a code-execution adapter. Alongside it are MLX LoRA training scripts and saved adapter weights. This is an implementation map; checkpoints and integrations have different levels of runtime validation.

01 / ROUTING

Task → model → tool

The current runner dispatches by intent keywords: quick reflex, web research, code, or longer reasoning. This is explicit rule-based routing, with room for a more robust classifier later.

  • 7B verifier + 1.5B draft path through MLX
  • 135M reflex path for short responses
  • Web scout and an Ollama/OpenInterpreter coding route

04 / WEB SCOUT

Search, scrape, synthesize.

toast1_fetch() queries the Hacker News Algolia API and, for company queries, extracts text from a company-data page. The result is passed to the 7B/1.5B generation path for synthesis. This is a targeted web connector, not a general search-engine crawler.

05 / CODE ROUTE

Local model, external executor.

run_autonomous_agent() configures OpenInterpreter against an Ollama-hosted UWOF model and enables automatic code execution. The adapter is present in source, but its current Python environment fails to import OpenInterpreter because pkg_resources is missing; the route needs repair and an execution-boundary review before use.
